## 文本模型定价：缓存写入价（Schema 82）

- 已实现：系统渠道模型的文本 Token 价格档新增「缓存写入」售价与成本价（每百万 Token），默认 0 表示缓存写入不单独收费；原「缓存」改名「缓存命中」。统一调价、渠道导入导出、公开目录和前台统一定价都带上该字段；视频 Token 必须为 0。
- 结算：调用日志与账单新增 `cache_write_tokens`。`input_tokens` 统一为含缓存命中和缓存写入的总输入，结算按“普通输入 + 缓存命中 + 缓存写入 + 输出”分别计价。预授权按输入价与缓存写入价中较高者估算输入 Token。
- 口径修正：Anthropic 原生 usage 的 `input_tokens` 不含缓存，此前按“输入 − 缓存命中”结算会少收；现在补齐为总输入，并读取流式 `message_start` 里的输入用量（此前流式只记录输出）。Claude 原生接口的扣费会因此上升到正确值。百炼读 `prompt_tokens_details.cache_creation_input_tokens`，OpenRouter 读 `cache_write_tokens`；其他网关把 `cache_creation_input_tokens` 放在 `prompt_tokens` 旁时口径不一致，保持原样不拆分。
- 本地验证：`go test ./...`、迁移测试、usage 归一与结算算术单测；`bun run typecheck`、`bun run lint`、价格档相关前端测试。未连接真实模型，未做浏览器验收。

## 请求协议插件：上游明确失败时调用日志与账单同步收尾

- 问题：中转站以 HTTP 200 返回 `{"code":"success","data":{"status":"FAILURE"}}` 时，插件解析器把任务判为失败；调用日志只认 `failed` / `cancelled` / `expired`，轮询日志仍记为成功并合并进计费根日志，失败任务的订单随之进入待核对。只在 manifest `output.task_status`、`errorPaths` 等位置表达的终态，日志侧完全看不到；音频轮询日志不合并，create 日志始终是成功。
- 已修复：`protocol.NormalizeStatus` 成为状态词表的唯一来源（补 `TASK_STATUS_FAILED` / `TASK_STATUS_PROCESSING`），调用日志复用它。插件解析出失败 / 取消终态时，宿主把同一终态写回本次任务的 create 根日志（`task_failed` / `task_cancelled`），再走失败退款；上游失败原因里的 timeout、524 等字样不再触发待核对。失败日志读取 `fail_reason`，外层 `code=success` 不再记为错误码。
