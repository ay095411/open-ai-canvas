电商Agent位于 `/ecommerce`，使用宿主现有登录、模型报价、任务系统和资源存储。用户上传商品图后，可配置平台、语言、图片类型、张数与视觉偏好，完成商品理解、方向选择和逐页策划，再确认报价并生成图片。详情图由 Agent 主动规划叙事与文案；未证实的参数、功效和认证不能作为商品事实。

`/ecommerce` 按五步走完一轮：准备素材 → 选视觉方向 → 图片方案 → 生成图片 → 导出交付。左侧展示方案与作品，右侧集中填写用途、商品素材和画面描述；页头提供「历史项目」「新建商品」。参考方式、描述短语及高级参数默认收起，展开后保留设置；描述示例追加到已有输入，已提交素材显示沿用数量和查看入口。简单场景可在「Agent 策划」与「直接出图」之间切换；复杂场景和参考分析使用 Agent 策划。

用途使用紧凑的单行按钮，详细说明放在悬停提示中。画面描述使用单层输入区域，保留多行编辑、粘贴与拖入图片；「参考设置」「常用描述」按需展开。控件与状态文案保持简短，作品标题、用户输入和错误信息完整显示。

底部主按钮随状态显示「推荐视觉方向」「查看并选择视觉方向」、按方案生成、继续生成剩余图片、查看进度或恢复已提交任务。Agent 先识别商品并推荐 4 套视觉方向，选定后自动策划并出图；「跳过选方向」直接写出整套方案，审阅后再出图。直接出图按描述与设置生成，跳过方向推荐和策划。回车与主按钮执行同一动作；查看已有方向、进度或点击顶部流程步骤只定位内容，不发起新的生成。窄屏会先切换对应作品／创作区，再定位内容。

一轮全部完成后，交付区提供图片下载与导出。电商Agent专注商品图片流程；通用图片与视频生成由独立「创作影棚」提供，地址分别为 `/toolbox/image` 与 `/toolbox/video`，在同一工作台中通过 Tab 切换。后台阶段模型不可用时，原因常驻在按钮上方并置灰按钮；页面提示统一走 `App.useApp()` 的 message，跟随明暗主题并去重。

## 功能开放与助手

后台「功能开放」按创作功能、插件与记录、模型与计费、页面辅助分组。开关展示保存值及未满足的依赖；关闭父项保留子项设置，重新开启父项后按保存值生效。

| 页面名称 | 字段 | 控制范围与依赖 |
| --- | --- | --- |
| 电商Agent | `ecommerceEnabled` | 电商入口、项目写入、识图、策划、出图与重试，不依赖影棚开关。关闭保留历史与已受理任务恢复 |
| 影棚图片生成 | `imageWorkbenchEnabled` | 仅控制独立影棚图片 Tab 的新任务、重试与重新生成 |
| 影棚视频生成 | `videoWorkbenchEnabled` | 仅控制独立影棚视频 Tab 的新任务、重试与重新生成 |
| 电商项目视频任务 | `ecommerceVideoEnabled` | 关联电商项目的视频任务，需同时开启电商Agent，不依赖影棚视频开关；当前电商页无独立视频流程 |
| 小夜助手（原站内助手） | `siteAssistantEnabled` | 总开关；还需开启积分计费及小夜自身配置，并满足人群和模型条件 |

创作影棚与电商Agent的入口和开关彼此独立。影棚位于「创作」之后，图片、视频任一开放就显示入口，默认优先图片；电商Agent位于「短剧 Agent」之后并带 NEW 标签，折叠侧栏保留新上线提示。影棚开关不控制电商、首页或自由画布。

新任务和重试提交前校验所属功能的开放状态，模型、权限与计费校验照常执行。已受理任务仍可查询和恢复；电商Agent关闭期间仅恢复到页面与本地缓存，保留回执并提示项目记录尚未同步，重新开放后可补同步，不创建新任务。

小夜独立配置页为 `/admin/settings/yoru`，可从「系统设置 → 小夜助手」或功能开放页进入，设置启用状态、开放人群、对话模型、形象、知识与导航。小夜与全局 Agent、画布内 Agent 独立。小夜配置变更后，同页及同源标签页收到通知，窗口重新聚焦或恢复可见时也会重读；关闭会收起面板并停止前端接收对话流，已受理任务继续按原计费规则处理。

商品图与借鉴图分别保存。参考方式支持商品自主策划、风格排版参考和详情长图逐屏参考。项目及其版本、任务回执与生成结果按用户隔离；删除项目保留资源及运行任务。作品区按批次展示本轮与之前的作品，显示完成与进行数量，可按状态筛选、批量选择、预览原图、修改单张、重试、下载、移除与导出。已保存的资源参与完成状态和下载判断，历史作品不依赖任务详情先加载完毕。

独立影棚的图片／视频历史在分页前排除电商项目任务，依据任务的电商来源、项目元数据或当前用户的电商项目归属识别。电商项目保留自己的历史，统一「创作历史」仍可查看全部任务；两者共用任务与资源基础设施，不复制任务或媒体，无需数据库结构迁移。

同商品连续创作从当前用户拥有的项目中读取最近 20 页已提交历史，继承商品资料与文案语气，以本轮要求覆盖旧要求。只有商品参考图有交集才关联历史，共享品牌 Logo、模特和借鉴图不能建立商品关联。历史文案不成为新规格的证据。普通商品策划逐屏分配机位、景别和购买问题，以 `displayAssignment` 随方案保存；输入新需求时保持已有结果与按钮稳定。

生成与策划统一使用安全边距、留白和商品避让约束；结果图按完整画幅显示。人物设定按目标地区与语言选择，每轮主动变化，同一套图保持身份一致；用户参考人物优先。肤质、景别和手部接触要求属于生成指导，不能替代成片检查。

平台选择与提示词共享随程序交付的平台资料，包含 SHEIN 在内的 36 个平台。已核实规则与待核实建议分别标记，待核实资料不能作为平台审核通过的保证。资料来源与使用边界见 [电商平台风格与图片规则](../overview/ecommerce-platform-rules)。

后台「电商 Agent」分组有两个页面。`/admin/ecommerce/agent`（电商Agent配置）的「上线检查」仅检查电商Agent开放与阶段模型配置，不要求开启影棚；开关仍在「功能开放」修改。模型可用性和费用在提交时校验。「阶段模型」只列实际执行的两个文本阶段：商品识别与视觉方向、整套策划（卖点文案、逐张分镜与生图提示词），各有主模型和备用模型，用与创作端相同的模型下拉，未开启识图的模型置灰并写明去「渠道管理 → 能力与参数 → 引用与限制」把「最多识别图片数」设为 1 以上；第三步出图使用用户在电商页选择的生图模型。配置仍保存在 `ecommerce_agent_orchestration_v1`：`director` 是整套策划；旧配置里 `director.reuse="marketing"` 时沿用 `marketing` 的模型，新页面保存时写入 `director` 并清空 `marketing`。未执行过的「视觉质检」阶段已移除。`/admin/ecommerce/library`（知识与技能）查看 KB01–KB19 知识域覆盖，管理固定来源同步、来源启停与条目审核。来源、版本和许可证随知识记录保留；覆盖数量不能作为各行业规则全部齐备的证明。检索使用数据库、关键词与规则，没有向量数据库依赖。

「知识与技能」页分视觉知识库、创作 Skills（`/admin/ecommerce/library/skills`）、行业品类（`/admin/ecommerce/library/categories`）三个标签；旧地址 `/admin/ecommerce-knowledge`、`/admin/ecommerce-skills`、`/admin/ecommerce-categories`均重定向到新页面。Skills 内置 61 个可执行创作方法包、许可证与版本信息，按商品和场景自动选择；管理员可启停、安装大包、改名并设置上游自动更新。行业字典包含 26 个根行业、64292 个中英文分类节点、搜索与祖先创作方法路由，覆盖分类不代表每个叶级品类均已逐项生成验收。

服务启动在离线包之后自动初始化 KB11–KB19、技能方法知识和行业类目。内置技能正文随二进制嵌入，类目字典随程序交付；新安装和升级不需要手工导入。管理员只需配置自己的文本、图片模型和两个阶段模型；实际模型调用仍使用宿主报价、权限与计费流程。

## 随程序交付的知识数据

`backend/internal/ecommerceknowledge/bundle/knowledge.json.gz` 随 Go 二进制嵌入 23 个知识源和 14740 条知识，包括 14739 条已通过、1 条已拒绝；KB01 有 11 条，KB02–KB10 各 10 条。`manifest.json` 记录来源、固定 commit、许可、分来源数量和 SHA-256，完整许可证与版权声明保存在数据包的来源记录中。

服务首次启动自动在一个事务内初始化离线数据，无需先访问 GitHub。安装摘要保存在 `system_settings` 的 `ecommerce_knowledge_bundle_receipt`；相同包再次启动直接跳过。版本变化时只合并缺失行，已有管理员修改、审核状态和停用设置保留。数据与安装记录一起提交或回滚，避免导入一半却被标记为完成。

维护命令在显式配置数据库位置后执行：`go run ./cmd/ecommerce-knowledge -bootstrap-bundled -admin <已有管理员ID>`。内置 KB01–KB10 的升级使用 `-bootstrap-builtin`，第三方固定来源在线同步使用 `-sync`。这些写操作需要已有管理员。数据包不包含具体部署的模型渠道绑定或凭据；部署后在四阶段配置中选择自己的模型。

HTTP 路由由 `backend/internal/handler/ecommerce.go` 和 `ecommerce_agent.go` 注册，业务在 `internal/app/ecommerce*`，持久化在 `internal/repository/ecommerce*`，领域契约与提示方法在 `internal/ecommerceagent` 和 `internal/ecommerceskills`。

`/api/ecommerce` 下提供项目、创意方向与技能提示接口；`/api/ecommerce/knowledge` 下提供知识与阶段模型管理接口，由服务端执行管理员权限校验。`/api/agent/quote`、`/api/agent/analyze`、`/api/agent/generate` 等接口提供独立 Agent 协议；`/api/canvas`、`/api/task` 下提供对应画布版本及任务查询接口。具体请求与响应以 handler 和前端 API 类型为准。管理员权限与用户资源归属均在服务端校验。

迁移 79 新增 `ecommerce_projects`、`ecommerce_knowledge_sources`、`ecommerce_knowledge_entries`、`ecommerce_creative_recommendations`、`ecommerce_agent_analyses`、`ecommerce_agent_runs`、`ecommerce_agent_pages`、`ecommerce_agent_canvas_versions`，包括知识域索引。保留上游 1–78 的迁移身份。电商图片读取使用 `ecommerce-export`，仅允许当前用户拥有的、32 MB 以内的 PNG、JPEG、WebP 原图，经受限同源流读取。

本次功能未包含旧版通用画布的一键详情／复刻节点，也不引入品牌、登录注册、支付充值或部署定制。真实浏览器、付费生成及已有部署的完整升级流程仍需人工验收；自动化数据库迁移和初始化检查不能代替这些验收。
